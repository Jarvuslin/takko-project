# Assessment boundaries

Written before paid dispatch. Keep contract, source assessment and native behavior distinct.

- Contract: raw strict decision validity, exact evidence/source bindings, permitted edits, format corrections and cost. A justified reject is valid but does not establish successful reuse.
- Ownership: does the output use the actual project scope and avoid constructing replacements for explicitly pending Marketplace needs? Does it distinguish component work from later tasks?
- Preservation: which original nodes and source bodies remain, and which behaviors are actually retained? Retaining geometry/media alone is not unchanged working behavior.
- Integration: are missing rig, animation, media, placement or cross-component interfaces stated accurately, without invented IDs, successful-playback claims or assumed dependencies?
- Code quality: independent source inspection of whatever behavior the model elects to implement, including state, lifecycle, timing and cleanup when applicable. A narrower manifest can avoid unrelated defects but cannot claim the omitted whole-game work as solved.
- Runtime: not tested by this harness. No success claim for visible motion, controls, counting, sound, export or full gameplay. Predicted inventory is not native recapture.

Fresh Gemini versus Sol receives identical corrected initial input. Historical old-context Gemini offers observational context evidence only; one response per treatment is insufficient for general or causal superiority claims. Do not turn fewer lines, cheaper calls or a valid manifest into an automatic quality win. Preserve every invalid attempt and qualification.
