# Component workers receive acquisition progress and ownership

V10's adapter received the complete game brief and an initial source review listing missing game mechanics, but could not see the actual namespace, the other declared Marketplace needs or the planned integration tasks. It generated a global procedural dummy while the separate rig need was still pending. The existing instructions already prohibited that replacement; missing context made the handoff incomplete rather than authorizing the behavior.

The pipeline now supplies a fresh host-derived `context.stage` to initial component review, adaptation and post-adaptation review. It contains actual scoped roots, current candidate, declared needs with truthful acquisition state, retained component provenance where valid, and accepted task ownership/dependencies. Unstarted or unknown needs are explicitly unverified. Task declarations are plans, never claims of implementation. Snapshots are cloned, and the namespace/tasks participate in the input identity used for retained acceptance.

Generic instructions distinguish component work from later game assembly: preserve useful content, do not procedurally replace pending acquisitions, and describe cross-component interfaces and remaining work. The snapshot neither grants coverage nor skips searches, native audio checks or required needs. It does not provide game-specific fixes, queries, IDs or code. Repeated native adaptation is still unsupported; safely adding it requires durable archive-chain handling, not simply changing an `if` into a loop.

The new task identity also has to account for normal build progress. A completed discovery-dependent task can register newly generated, validated files before a later task requests another asset. Reuse comparison permits only that append-only registration when the files actually exist in the retained artifact and ownership/scope checks pass. Changed task metadata, dependencies, requirements, removed files, unfinished-task additions or foreign paths still invalidate acceptance. Immutable component records keep their original identity; the current context binding advances through the existing validated reuse path.

The assessor now accepts the new optional scope/task fields and the previously omitted optional component-reviewer profile, with strict profile/hash validation and legacy omitted-field support. Focused suites passed197 stage/pipeline/Engine/assessor tests and26 final assessor tests, plus TypeScript. Final `npm run check` passed **1,126unit/API +10desktop +36browser tests and all stages**. No application source changed afterward.
