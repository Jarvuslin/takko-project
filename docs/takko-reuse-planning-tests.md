# Reuse planning, retained coverage and request deadlines

2026-09-16. These changes remove concrete obstacles to reusing complete Marketplace components. Their offline tests pass; fresh worker effectiveness is measured separately in diversity v5.

The planner and design guidance now ask for reusable behavior systems and embedded animation/media before replacement scripts. Discovery-dependent tasks may defer file ownership with `files: []`. Importer limitations cannot authorize silent procedural substitutes. These instructions do not guarantee model compliance.

Previously, task coverage could cite generated files or scene nodes but could not cite an already retained native component. This could force unnecessary duplicate implementation. The Engine now revalidates server-owned integration records and permits coverage to cite their exact root paths. Arbitrary paths and missing integration still fail. A regression completes a task with no new files or scene nodes when the retained implementation supplies its requirements. This is an offline integration test, not a gameplay pass.

Provider profiles may explicitly set `requestTimeoutMs` from 1,000 to 600,000. The default remains 120,000. Diversity v5 gives only its worker 300,000 ms after the raw v4 worker request timed out at 120 seconds. Spending caps, reservations, cancellation and conservative charging of unknown outcomes are unchanged. Thirteen tests cover default/configured deadlines, cancellation, settlement, bounds and a simulated valid response after 125 seconds. Simulation does not establish that the actual provider will complete within the longer deadline.

`npm run check` passed with **953 unit/API tests, 10 desktop tests and 36 browser tests**, plus Luau, plugin, guard, build and production checks. Full log: `research/results/reuse-planning-v1/check.log`. Native runtime-marker evidence is recorded separately in `docs/takko-runtime-touch-tests.md`.

Fresh v5 uses unchanged frozen user briefs, unchanged model routing, unchanged $1 project and $6 campaign limits, an isolated current-source service, and automatically restored local encrypted credentials. Raw plans, selections, review/adaptation outputs and failures remain unedited. See `benchmarks/runs/marketplace-diversity-v5-20260916/PROTOCOL.md` and case artifacts for actual outcomes. A relevant asset selection or a source-review pass alone does not prove a playable game or improved average quality.

Follow-up source review found two remaining inconsistencies in the top-level system prompt and task schema. These were removed and a provider-bound regression verifies their actual outbound delivery. The v6 controller also supports an explicitly selected shared Gemini worker/planner profile, with a settings-restoration regression. The full check for these changes passed 955 unit/API, 10 desktop and 36 browser tests. Log: `research/results/reuse-planning-v1/final-check.log`.

Fresh outcomes limit the effectiveness claim. V5 bubble still timed out after 300 seconds, below the $1 cap. V6 Gemini parkour completed component adaptation but omitted a moving-platform discovery need and encountered an audio test-environment blocker. Its exact selected sound subsequently passed isolated native inspection and placement replay, separately from the failed worker trial. V6 combat had a five-hour timestamp gap and is excluded from latency conclusions. The prompts now reach the provider consistently, but the raw planner still does not reliably cover requested behavior reuse. Further model/configuration evaluation or a semantic planning gate is needed; more budget alone is not an established remedy.
