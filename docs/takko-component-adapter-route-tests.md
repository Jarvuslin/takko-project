# Separate component adaptation model

The prior context-matched repair diagnostic found stronger static authority and integration in Sol's answer, with unresolved lifecycle defects. Takko now supports an explicit optional `routes.componentAdapter` profile so a full-pipeline test can change the adaptation worker without changing asset selection, audio evaluation or ordinary building. This is a routing capability, not evidence that the selected model produces a correct game.

The route accepts at most one configured profile. Both bounded adaptation attempts and their existing format-correction calls use it; absent or empty routing preserves builder inheritance. Startup validates the selected profile/model/key before native access. The full explicit profile is included in asset context identity, so changing a route or its configuration invalidates retained evidence rather than silently reusing it under different assumptions.

The benchmark accepts `componentAdapterModel`, resolves a unique keyed profile before mutations, applies the override only when supplied, records effective settings in the experiment/result, and restores the original settings. General builder, source reviewer and audio routes remain independently selected. No UI default or product-wide model switch was made.

Independent review found no route blocker. A test-wrapper restoration issue was also fixed: restoration now requires explicit local completion and no native reconciliation requirement. Seven offline decision cases and actual wrapper ordering passed; that test is not native restoration evidence.
