# Reviewing whether component adaptations preserve behavior

Takko previously replaced the original review evidence with the recaptured adapted evidence before calling the reviewer. The reviewer could inspect the current code, but could not compare useful behavior or configuration with the original sources or verify the adapter's preservation claims.

`src/generation/component-preservation.ts` now constructs a bounded host context after adaptation. It checks matching candidate, token, game input and original archive identities; validates source hashes and bindings; reuses the durable adaptation inventory algorithm; and compares expected nodes, sources, source settings, media and configuration with recaptured evidence. It records original-to-current indices, removed nodes, added sources and each source binding's actual change. The pipeline snapshots original evidence and the validated plan before passing copies to the adapter.

The Engine presents original and current numbered sources in separate namespaces. Applied-plan replacement/addition bodies become references to current source hashes so code is not repeated in the plan. Generic instructions ask the reviewer to compare behavior, configuration, lifecycle and integration dependencies and distinguish worker claims from evidence. This is additional context, not automatic semantic acceptance: existing strict response validation and current-source citation authority remain unchanged. The raw response is retained. Initial reviews keep their old input shape, and durable component evidence/records remain compatible.

Tests cover the actual pipeline and Engine prompts, grouped replacements, removals, additions, matching persisted mappings, defensive snapshots, foreign identities, altered sources/settings/configuration, rejected before-only source citations and nonrecursive context. Native application/export semantics are unchanged; offline tests do not establish runtime behavior.

The preregistered [context comparison](../research/results/component-preservation-v1/PROTOCOL.md) uses an unchanged V9 moving-platform adaptation. It measures fresh reviewer output with versus without this context, with the same model, current sources, schema and generic instructions. Independent findings are held outside the model prompt. See its results for effectiveness and limitations; contract validity alone is not a semantic or game pass.

Full `npm run check` passed on rerun: **1,066 unit/API, 10 desktop and 36 browser tests**, plus all other stages. An initial Windows test-worker crash is preserved separately. The [paid comparison](../research/results/component-preservation-v1/RESULTS.md) cost **$0.054825**: both first-attempt reviews passed the contract, but both missed all three targeted preservation losses. The treatment described integration limits more accurately. This verifies the context fix while leaving semantic reviewer effectiveness unresolved; there was no native/gameplay test or live-app restart.
