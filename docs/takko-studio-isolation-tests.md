# Reversible Studio test isolation

The v6 parkour run reached audio verification and stopped because an older root-owned fixture left a second Studio process open. After closing only that verified fixture process, a replay of the exact worker-selected audio correctly rejected the active scripts in Place1. Neither failure establishes that the chosen sound is appropriate or that the game works.

`scripts/studio-test-isolation.ts` generates bounded, nonce-owned Edit-only pause/restore operations for a controlled test environment. It does not edit script sources, choose assets, repair model output or initiate Play. Before changing any flag, it captures all relevant script identities, parents, names, classes, editor-source hashes and original Disabled values in a ServerStorage recovery record. Restore checks every original before writing any flag; unexpected source, identity, record, enablement or phase changes preserve the record for reconciliation. It removes only its own validated record. Scripts in ServerStorage are excluded from execution isolation.

Fifteen emitted-Luau tests cover exact round trips, originally disabled scripts, unrelated new scripts, source/identity/ownership changes, preflight failures, count limits, unexpected enablement and uncertain phases. These are simulated service tests. A native Edit round trip subsequently paused and restored the three actual existing scripts with no source edits and no Play transition. Evidence is recorded separately from the raw game benchmarks.

The isolated audio replay uses the worker's saved query and exact selected asset, refusing substitution if it is no longer returned. The production adapter owns audition, recording and cleanup; the harness restores original script states afterward. This tests audio infrastructure under a prepared environment. The product still deliberately refuses audition in an ambiguous or active place; the diagnostic helper does not silently weaken that guard.

Native audio replay outcome and final full-check counts are recorded in diversity v6 RESULTS and the corresponding evidence directories. A completed audio recording alone does not establish game synchronization, listening quality, or full native acceptance.

The native replay passed both inspection and placement auditions of the frozen worker-selected sound, reaching its natural 2.848-second ending and recording fresh process-bound WAV evidence. The three original scripts were restored afterward. A later raw combat run was interrupted by a five-hour timestamp gap; its finally-restoration also passed. Final native evidence confirms Edit, originals enabled and no owned audition/isolation/combat leftovers. See `docs/results/takko-studio-isolation/`.

Final **`npm run check` passed 970 unit/API, 10 desktop and 36 browser tests**, plus all remaining stages, exit 0. Log: `research/results/studio-isolation-v1/check.log`. A preceding check overlapped the timestamp gap and failed one mobile model-picker assertion; its log remains `interrupted-check.log`. The rerun passed without weakening or modifying that assertion. These checks validate infrastructure; no complete raw generated game passed acceptance.
