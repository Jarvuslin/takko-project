Changes:
  - pass --print-logs and --log-level DEBUG on the spawn in opencode-runtime.ts
  - capture and RECORD the child exit code and signal, never discard them
  - capture stdout and stderr and include them in the failure record and the reported
    error, bounded in size
  - a failed runtime job must report exit code, ref, and the last N log lines

This is observability only. Do not change the runtime protocol, session handling, or
the 48-exchange / 900-second ceilings.

## FIX 2: audio capability mismatch

providers.ts:70 sends the actual audio to the evaluation model but only validates the
TRANSPORT:

  if (profile.provider !== "gemini" && profile.provider !== "openrouter")
    throw new ProviderError("Audio input requires ... audio-capable model ...");

The comment above it already concedes the gap: "Protocol support does not establish
that the configured model accepts audio." The configured model is Sonnet 5 via
OpenRouter. Claude models do not accept audio input, so the request 404'd. That is a
model capability mismatch, not a selection problem, and it burned a $0.601792
reservation on a call that could never succeed.

Fix by checking MODEL capability before dispatch, not just provider. Then either route
audio evaluation to an audio-capable model, or evaluate on captured metadata without
sending audio. Do not send an audio payload to a model that cannot accept it, and do
not reserve budget for a call that will be refused.

Also check the reservation path: a 404'd call should release its hold rather than leave
$0.60 outstanding.
