# Remaining fighting-game acceptance checks

This is the evaluation checklist, not a generated architecture or evidence of a working game. Execute after the paid retry and Studio target confirmations arrive. Continue the existing isolated project and include its first failed call in the $4.40 total cap.

1. The accepted concept retains fist fighting, Marketplace animations, a practice dummy, attack/impact VFX and SFX, and a visible hit counter. It introduces no weapons, kicks, PvP or AI opponents. Every proposed player action has an observable expected outcome.
2. The generated architecture maps input and presentation on the client, validates attack timing/range/hits on the server, and sends confirmed hit state to the counter UI. The dummy, animation and effects responsibilities have real connections. Equivalent combined systems are acceptable. Build task dependencies alone are not runtime connections.
3. The approved animation clip matches the actual player rig and visibly performs a punch. A pack's model ID must not be mistaken for a playable animation ID. Native playback permissions and integration must be demonstrated. Readable preview tracks alone do not establish this.
4. The dummy is the selected asset or an explicitly approved equivalent. Animation, model and effect choices remain references until inspected and approved. Do not silently replace requested Marketplace content with placeholders. Verify real VFX in Studio and listen to the chosen SFX before marking suitability passed.
5. A valid punch starts its animation and intended attack feedback. One confirmed contact increases the visible hit count by exactly one and triggers one impact response. Misses leave the count unchanged. Five additional valid hits add five. Rapid repeated input does not produce duplicate counted contacts or bypass the chosen cooldown.
6. The hit-counter display is readable at the normal and minimum window sizes. Respawn does not leave duplicate input listeners or duplicate counters. A stale/deleted dummy does not throw errors. Observe the actual playable experience and Studio output, rather than accepting compilation or a model review as proof.
7. Verify chooser scrolling, preview orbit/scrub/pause, pointer and keyboard focus, button alignment, back-to-results state, clip selection and explicit approval. Record unsupported previews and unavailable media honestly. Do not count a metadata-only view as audio or particle playback.

Record every model charge, conservative reservation and updated provider balance. Do not automatically retry another failed paid trial. Preserve failure artifacts. For native work, use only the confirmed place and a scoped test namespace, restore original scripts, remove temporary test imports/probes, stop owned services and leave Studio in Edit mode.
