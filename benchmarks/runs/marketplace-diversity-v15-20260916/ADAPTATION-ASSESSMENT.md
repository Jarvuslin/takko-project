# V15 independent adaptation assessment

V15 produced one substantive Sol adaptation, applied and recaptured in native quarantine. The subsequent source-review request was refused locally because its reservation would exceed the project budget; there is no post-adaptation model verdict. The run failed without an accepted component, export or gameplay test. Its five known calls cost $0.3769847 (376,988 rounded microdollars). This is a budget-limited outcome, not a measured semantic rejection or acceptance of the adaptation.

Evidence inspected: final project/events, the unchanged raw adapter response in `bubble-wrap/model-events.jsonl`, adaptation sidecar `b21769f37aebcdda6eb0ac61dc903a103236928c77b5367b382fb5511f1ec619.adaptation.json`, and native recapture manifest `040021498f0f4c5f6a21b4447cdf8efdf8b37ecf1e404dbc3e476c6572c4187a.component.json` under `bubble-wrap/asset-evidence`. Sidecar/manifest/source hashes were independently checked. The added source in the native manifest exactly equals the raw worker source. No game code or model answer was changed for this assessment.

## Actual preservation and replacement

The worker removes the original regeneration Script subtree at index 4 and unrelated dynamic-loader subtree at index 15. It replaces all 72 repeated bubble scripts with the same 180-byte no-op source (`98fe3293…`) to avoid competing listeners, then adds a 7,702-byte server `BubbleSheetController` under the retained sheet. The captured inventory changes from 375 to 367 nodes and 76 to 73 source bindings. No original source body remains byte-identical. All 72 nonempty SoundId references remain unchanged, and the authored sheet/target/mesh/detector/sound hierarchy is retained rather than replaced with procedural geometry.

This is substantial behavior reimplementation around retained Marketplace content, with semantic preservation of direct per-target activation, target locking, attached pop sound and whole-sheet recovery. The replacement stubs do not make the entire result inert: the new controller actually connects each detector to active logic. Conversely, retaining media and re-expressing the original behavior does not prove working runtime reuse. The native manifest records `executed: false`, `runtimeVerification: not_performed` and successful serialization round-trip only.

## Static behavior assessment

Line references below refer to the exact added controller, SHA256 `1b7ce5fd8728e712766bbc738c9b0894baf61163ce4ce35c54e5a7f737272a0e`, captured at current index 366.

- Lines 33–52 discover only direct children of the retained sheet, requiring a detector and attached Sound. There is no global world scan or external require. Lines 156–187 connect direct clicks, retain original visual baselines and assign server-side bubble IDs.
- Lines 121–140 reject non-Fresh/resetting targets, validate a current player's root distance, rate-limit per player, enter Popping and disable the detector before scheduling work. This is a real explicit state guard beyond the original detector-only callback.
- Lines 142–152 play the retained sound after the press interval and schedule completion. Lines 102–118 recheck generation/state, mark Popped, change transparency, increment once and emit count/completion events. Count remains server-owned; later integration must not count the same event again.
- Lines 190–248 validate a deliberate remote reset, player proximity and cooldown. Reset increments the sheet generation, locks all targets, stops sounds, restores baselines and returns count to zero before releasing Resetting. Old pop callbacks check the generation at both scheduled stages. This materially addresses stale post-reset increments; the source does not reproduce the earlier unguarded reset/callback pattern.
- Lines 28–31 and 62–67 expose scoped reset/events and readable state attributes for later HUD glue. Lines 255–273 clear rate tables on departure and disconnect listeners/invalidate callbacks when the controller is destroyed.

The reset policy allows a reset after any committed pop, including while other pops are pending, and safely rejects reset while the count is still zero. It does not require completion first. Early reset availability is not an explicit user requirement; safe rejection of a pending first pop's reset is not itself a defect.

## Remaining risks and deferred integration

1. **Visual phases are an approximation, not verified motion.** The press tween and subsequent settle tween use the same flattened goal (lines 82–99, 140 and 149). The second tween does not define a separate recovery pose; final transparency changes at line 109. The sequence may read as compression followed by sound and a delayed transparency change. Whether that satisfies visible popping/settling requires actual observation. Fixed delayed callbacks, rather than Tween completion signals, also mean static code does not prove the counter follows the animation's observed completion under load.
2. **Session lifecycle is incomplete.** PlayerRemoving only clears rate-limit tables. It does not invalidate that player's pending pop, reset sheet state, or cancel work on character replacement. Distance is checked at admission, with no later player/character check before commit. Completing an already accepted pop after departure is not automatically wrong for shared world state, but the worker's own remaining-integration note requires enforcing the one-player session context; fresh-session/rejoin/respawn behavior remains unproved.
3. **Touch and presentation remain legitimately pending.** There is a reset RemoteEvent but no client HUD or alternate pop RemoteEvent; current activation uses retained ClickDetectors. The worker explicitly defers native touch qualification and any compatible alternate input integration. Table/camera/HUD construction and audio acquisition are separately owned tasks, so their absence here alone is not an intrinsic component rejection. Any alternative input must reach the same controller instead of creating a second state owner.
4. **Geometry and audio assumptions require qualification.** Compression uses local mesh Y; baseline positions, scales, translucency and detector distance are reused without observed camera/orientation testing. The controller targets the full retained sheet, rather than forcing the plan's inferred twelve-bubble subset. Sound playback calls retain provenance but do not establish availability, audibility, fit or synchronization. The pending Audio need was not completed.
5. **Integration must preserve controller ownership and target lifetime.** Bubbles are discovered once at startup and callbacks retain those instances. No dynamic target-removal/replacement handling is implemented. Later glue must respect that interface or obtain a worker-authored integration change. Contract-name collisions cause `getOrCreate` to return nil while other behavior may continue; no collision was identified in this captured hierarchy, so this is an integration precondition rather than an observed failure.

The raw answer and native recapture parse as structured evidence and match byte-for-byte for the added source. This assessment did not compile or execute the Luau and makes no compiler-pass claim. In the inspected source there is no obvious new external dependency or visible syntax defect, but that is weaker than parser/runtime verification.

The initial unsafe chain was actually removed and useful content was retained; the new state/reset logic is materially more complete than inert stubs. Its later source-review quality, playback, behavior preservation in operation, whole-game integration and desktop/touch acceptance are unmeasured because the run stopped at the budget reservation. Root's closure evidence reports restored original scripts and no owned leftovers; this reviewer performed no native or paid operation and supplied no worker corrections.
