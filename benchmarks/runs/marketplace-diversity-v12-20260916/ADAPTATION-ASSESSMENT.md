## Concrete defects and integration risks

1. **Reset can resurrect an old pop.** Lines 16–28 clear the lock and restore state/geometry, but do not cancel either tween, invalidate an in-flight handler, or stop audio. The old `onPop` can resume after lines 46 or 63 and play audio, alter geometry, and set `Popped=true` after reset. A new click accepted after the lock clears can overlap that old handler. A future attribute-listening counter could therefore count stale work on a fresh sheet. This is a static control-flow defect whenever reset is allowed during a pop; no native reproduction is claimed. Restricting reset to a completed sheet could avoid this trigger, but the current component interface does not enforce that restriction.

2. **Acceptance validation is absent from the actual pop entry point.** `onPop(player)` at line 30 never uses `player`; the only guards are local busy/popped state. There is no explicit player-health, distance, per-player rate, active-sheet membership, or selected-subset check before visuals and audio begin. The ordinary ClickDetector provides targeting infrastructure, but cannot be counted as proof that the accepted plan's validation requirements are fulfilled. Merely adding a central counter listener would not validate the already-triggered sound and animation. This is an unresolved component interface responsibility, not a demand that this adaptation implement the entire game.

3. **Reset overrides detector configuration.** Line 21 sets `MaxActivationDistance=32` rather than restoring its captured initial value or an agreed integration setting. Later placement/range decisions can therefore be invalidated by reset. The interface also requires changing `ResetTrigger`; repeated assignment of the same attribute value is not a new change event, and that usage contract is not explained in the manifest's remaining-integration list.

4. **Missing dependencies are tolerated as apparent completion.** Absent mesh substitutes waits; absent Sound skips playback; completion attributes are still set. The currently captured bubble hierarchy does supply the relevant objects, so this is not proof that this particular archive is missing media. It is a fail-open behavior if later subset/layout integration changes those dependencies. Sound availability/loading/listening remains unverified even when the Sound instance exists.
