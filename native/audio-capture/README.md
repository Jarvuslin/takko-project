# Process-scoped audio helper

Original C# COM/PInvoke implementation of Microsoft's documented WASAPI process-loopback interfaces. No sample source was copied. API design reference: [Microsoft application-loopback sample](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/) and its [IAudioClient activation sequence](https://github.com/microsoft/Windows-classic-samples/blob/main/Samples/ApplicationLoopback/cpp/LoopbackCapture.cpp). Microsoft sample licensing remains with that upstream repository; this implementation uses its public API concepts and declarations.

Build with `node scripts/build-audio-capture.mjs`. This uses only the existing absolute Framework64 C# compiler path. No Python, installer, SDK download, PATH compiler lookup, microphone, endpoint-wide capture, or exclude-process mode exists.

Arguments: `--pid N --started-at ISO --duration-ms 500..8000 --output ABSOLUTE_WAV`. Preserve the target's exact creation timestamp, including seven fractional digits (`Process.StartTime.ToUniversalTime().ToString("o")`). The parent must separately authorize the target executable and bind it to the selected Studio. Capture includes that PID **and its process tree**, not unrelated processes. The helper verifies creation time before and throughout capture. Output must be a new `.wav` directly within a caller-created `%TEMP%/takko-audio-*` directory; reparse-point directories are rejected.

The helper emits JSON lines. `event: ready` means capture has already started; the parent can then trigger its owned sound. `event: complete` includes PCM16/stereo/44100Hz WAV metadata, SHA-256, peak/RMS, packet counters, and `semanticVerified: false`. Duration is at most eight seconds and output is capped at five MiB. Silence or successful capture is not proof of asset audibility, ownership, semantic relevance, or visual quality. The parent must inspect actual samples, establish receipt identity and supervise total process timeout/cancellation. `event: error` means no capture success; partial output is deleted where possible.

Native QPC timestamps preserve the measured startup gap as leading zero frames (`leadingSilenceFrames`). Missing initial timestamps or a gap over 250ms fail; the helper does not silently trim that gap. Subsequent samples come from WASAPI, including its silent packets. Capture can end slightly before the wall duration because of packet buffering; the completion receipt reports the actual WAV duration. No trailing padding is invented. Completion is emitted after the WAV is flushed and closed. The parent should require enough real native baseline after the reported startup gap. An independent watchdog bounds the entire helper lifetime to the requested duration plus ten seconds.

The helper also provides an explicitly separate `--selftest-tone-hz 200..2000 --duration-ms 500..8000` mode. It generates only an in-memory synthetic sine tone in its own process after reading `START` from stdin. It is for supervised native isolation tests only, not asset playback or production scoring. Automated test fixtures do not record Studio or user applications. Run `node native/audio-capture/selftest.mjs` explicitly to capture one owned tone process while another owned process plays a different tone, and verify exclusion plus the quiet baseline.
